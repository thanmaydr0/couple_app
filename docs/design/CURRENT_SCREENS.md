## Chat receipts and optimistic-send provenance

- `src/features/chat/model.ts`: ChatMessage adds `status: sending | sent | failed`; `asSent` marks server rows sent; `mergeMessages` deduplicates by client_id, preserves read_at and prevents a late failure replacing a server-confirmed send. “Seen” is derived, not a fourth stored status.
- `src/features/chat/useChat.ts`: `send` creates a UUID/client_id, local created_at, read_at=null, optimistic sending state. `transmit` persists the outbox then calls sendMessage, merging success or failed. Retry reuses client_id. `markRead` updates other sender's unread rows through latest loaded sent timestamp only while conversation focused and foregrounded. Realtime INSERT/UPDATE and refresh receipt queries merge returned read_at values.
- `src/features/chat/service.ts`: sendMessage first checks client_id to recover ambiguous success, uploads images then inserts; returned created_at is canonical server send time. `loadCache` converts unfinished sends to failed for explicit retry after restart.
- `src/features/chat/Screen.tsx`: every outgoing row shows timestamp then `◷ Sending`, `⚠ Failed` or `✓`. Only the latest outgoing message displays `Seen ♥` underneath when read_at is present. Incoming rows have timestamps but no receipt. Current UI does NOT draw double ticks, animate clock/tick, or expose Message info.
- Proposed presentation derives seen when status=sent AND read_at is non-null. Never infer delivery/seen from typing, online status or local enqueue. For pending/failed messages created_at is local enqueue time, not a confirmed sent time.

## Scope boundaries

Unused scaffold files: src/features/auth/Screen.tsx, home/Screen.tsx, games/Screen.tsx, settings/Screen.tsx and features/auth/AuthGate.tsx are not the active route implementations. Appearance, arbitrary accent selection, animation preference persistence, chat action sheet and Message info sheet are explicit design requests but not currently implemented. No registration, password reset, couple invite flow, media reactions, movie catalog or additional games should be invented.
