# Two-phone Watch test

Use two Android phones with the existing development build containing the already-installed Expo modules. Do not perform a local native build or install packages during this wave. Sign in with the two accounts linked to the same couple. The Watch broadcast policies in `setup.sql` must be applied (completed on the configured project). Have internet access for control messages and sufficient device storage. No Firebase setup or video-upload service is required.

Put an unprotected MP4 copied from the **same original** on each phone before opening Watch. Use a second file with a different size/duration for mismatch checks. Do not use Netflix or other DRM/streaming-app downloads. Record Android versions, device models, codec, filename, bytes and duration when reporting a failure.

1. **Create and discover.** On A, open Watch → Pick a movie & create session. Pick the local MP4. Confirm B gets a join invitation within 10 seconds without manually refreshing. A cannot play before B selects its copy. Cancel B's file picker: A must still be blocked.
2. **Match and reject.** B chooses the second/different movie. Confirm the mismatch shows exact expected and actual bytes and duration in ms, and blocks joining. Cancel the override confirmation. Re-pick the original matching MP4; confirm both show ready. Repeat with a duration difference greater than 1,000 ms and, if available, equal size but a different duration. Exactly 1,000 ms is allowed. Exercise the different-cut override separately; confirm explicit consent permits playback and warns about scenes not lining up.
3. **Either controller.** A plays, pauses, seeks on the bar, uses −10s/+10s, then B repeats. Seek both while paused and while playing. Verify paused seeks stay paused. Check beginning/end clamping and automatic pause at the end of the file. Repeatedly tap controls on both phones at almost the same instant; the latest winning command must converge without a ping-pong loop. Remote pause/seek shows a toast.
4. **Measure sync.** Film both screens with a third camera using an MP4 with visible timecode/claps. Play for at least five minutes and compare displayed time/frame/audio. Confirm ordinary drift is corrected below the 0.2s target; forced drift over 0.6s should visibly seek, smaller drift should converge gradually. Watch latency/drift diagnostics and check that rate returns to 1.0. Repeat on separate Wi-Fi/mobile networks. Set one phone's wall clock ahead (if possible), reopen both, and repeat. Frame-perfect/audio-perfect alignment is not guaranteed.
5. **Buffering and stalls.** Try a slow external local storage provider or briefly interrupt access to a test copy. If either player reports loading, both must pause. On recovery both become ready and resume together. If an access/decoder failure persists, an actionable error must appear; retry playback/re-pick the file. Pausing manually while buffering must cancel auto-resume. A decoder that freezes without a status transition may require the retry button.
6. **Disconnect and return.** Enable airplane mode on B while playing. A must pause after at most ~12 seconds without partner messages; delivery failures may pause sooner. Restore B's internet. Both reconnect and exchange readiness; press Play to continue. Go Back on B, then use Quick return on Watch. Check the waiting banner on A and that the session stays available. Background/lock B: both pause; bring B back and explicitly play after readiness. Check Android audio-focus interruptions from a system call.
7. **Controls and fullscreen.** Drag the seek bar; check time labels, ±10s and disabled controls before both ready. Enter landscape fullscreen, toggle the overlay, seek/react there, use Android Back to exit, then leave the route. Confirm prior orientation is restored, system brightness/volume remain usable, video never overlaps a second player, and the screen stays awake while watching/waiting. Test on a small display and with large system text.
8. **Reactions.** Send each emoji from both phones. Confirm each appears once locally and once on the partner phone, floats upward and fades. Rapid reactions must not alter playback.
9. **Resume and URI expiry.** Seek to a recognizable time, leave both screens without ending the session, reopen and confirm A/host's saved position is used and both wait for ready. Force-stop and restart; up to four seconds can be lost. Clear only a temporary cache copy or revoke a document grant; confirm re-picking works and that the original device file remains. A previously overridden different cut must ask for confirmation again on reentry.
10. **End and isolation.** End from either phone. Confirm the partner receives the end, cannot play again, and can start another session. Temporarily disconnect the partner before ending; reopening must fetch the persisted end. Inspect device storage: originals must still exist. With an unrelated couple account, verify session rows, invitation changes, and `watch:<id>` broadcasts are inaccessible. The automated live check covers anonymous and nonexistent channels; a third couple account is needed for this final authenticated isolation test.
